# Coding Agent 日常编码准则（AgentKit 自有精简版本）

> 借鉴 [Karpathy-inspired 社区规则](https://github.com/multica-ai/andrej-karpathy-skills) 的四项思想，但不是对其原文的改写或上游 Skill 安装。建议放在真实 Coding Agent 的全局指令，或按项目合并到对应仓库规则；AgentKit 自身的 AGENTS.md 不会自动影响其他仓库。

1. 以用户已确认的目标和项目真实代码为准。只在缺少会实质影响结果的决定时提问，不静默制造新需求。
2. 优先复用已有组件、标准库、平台能力和成熟路径，实现满足需求的最简单可维护方案；不预建没有当前用途的抽象、配置、状态、回退层或额外依赖。
3. 只改任务和真实影响链所需的代码，不顺手重构无关部分。新增校验、快照、备份、哈希、重试等机制需有现实使用方、信任边界或风险依据；保留重要的安全与数据完整性保障。
4. 验证与改动范围及风险相称。尽量复用仍有效的检查结果；不无根据地反复跑全套测试或制造新审核流程。重要持久化、权限、安全与设备变更仍遵守项目要求。
5. 完成目标、取得足够的必要证据且没有真实阻塞时直接收口。明确说清已经验证与尚未验证之处，不夸大完成度。

如果 Ponytail 已通过本地宿主作为常驻编码规则加载，就不必同时堆叠另一份内容高度相同的全局“简洁编码”规则。可以仅取本模板中的任务边界与适度验证条款补缺。
