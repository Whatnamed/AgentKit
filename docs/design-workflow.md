# 从产品想法到可开发前端：AgentKit 使用路线

> 用户自己用的工作方法，不是每次必须完整执行的自动流水线。Skills 可以随时单独触发；简单问题回答简单，完整新产品则需要推进到具体细节。
> 正式规范以各 Skill 的 `SKILL.md` 为准，本文只是便于跨窗口/跨 Agent 使用的路线图。

## 0. 从几句需求开始也可以

示例：“我想做一个管理多个模型测试组的桌面工具，有题库、单题执行、提交、统计。先用 AgentKit 帮我从产品定义做到详细 IA 与交互。暂不做视觉，关键产品选择由我定；该补的功能和小细节主动补齐。”

**产品与 UX Plugin**：
1. `product-discovery` 整理用户、任务、业务对象、数据事实、功能边界，并主动补漏；有完整需求时可跳过。
2. `product-ia-interaction` 先确认导航和页面职责，再一页一页细化：空间区域、分组、优先级、列表/表格/详情设计、各控件动作、状态、异常、恢复、狭窄窗口和实际工作路径。**不能只停在一张高层框架图或 demo。**
3. `product-ux-review` 需要时检查关键遗漏、取舍与真实任务闭环。完整方案已经合理时直接收口，不强制循环审查。

每次可以先展示一部分方案让用户调整，设计决定按确认状态进入产品文档；用户不必一次输入完整 PRD，也不需要每个步骤都打长 Prompt。最重要的是**关键产品决策不是 coding agent 自己补齐的**。

## 1. 产品定稿后选择视觉路线

**已有喜欢的风格/设计系统**：“视觉采用 ProxyLens 指定版本的设计语言，应用到我已经确定的页面，不要复制 ProxyLens 的页面和导航。包括字体/行高/区块层级/空间节奏/表面/控件/两套主题，尽量做完整。”

- `visual-system-extract`：来源信息没有现成可携带版本时先提取，固定 commit、Source Map、可授权资产。
- `visual-system-adopt`：每个目标页面按视觉角色映射，覆盖文字、留白、密度、控件各种状态、Layer、Dark/Light、窄窗。不得以颜色字号近似就说完成。

**想重新做一套视觉**：“产品 IA 已定，请用 `visual-system-create` 帮我先选视觉方向，再在代表页面上实际调整字体、配色、间距、密度、行高、表面和组件，定下来同步成完整设计系统。”

- 从视觉方向与代表页面开始，用户可以反复反馈局部观感。
- 变动首先判断属于全局 Token、组件规则还是页面例外；最终确保新产品的视觉系统和已定的产品 IA 对齐。
- “方向确定”“代码完成”“真实运行验收”三个状态不能混淆。

## 2. 开发与后期微调

“现在按仓库中的产品 IA/UX 和设计系统开发 UI。用 `personal-ui-delivery` 先核对权威文档和已有代码，照逐页规格实现，缺重大产品决定不要自行创作；检查真实状态/字体/间距，修改后同步适用文档。”

此 Skill 适用于本地 Coding Agent；ChatGPT 也可以按其规范审查代码与交付计划。关键问题：
- 用户能否通过实际 UI 完成每条重要任务，还是只存在看起来能点的控件？
- 页面结构是否忠于产品规格，不受早期 Demo 或其它产品布局束缚？
- 字体是真实渲染正确还是只有 CSS 属性正确？空间、字重、行高和选中/hover 有无互相干扰？
- 修复后是否更新 canonical 文档，并且知道何时应该停下？

可根据需要使用 `visual-qa` 做视觉复审，不是每次修改都必跑完整矩阵。

## 3. 什么叫这一套“做完整了”

产品前端部分：主要对象/功能真实，IA 清晰，**每个核心页面有模块与控件级详细布局和交互**，重要的成功/失败/空白/未知/恢复都可解释。不是仅列页面和功能名称。

视觉部分：统一且可使用的设计系统，涵盖字体和字重、空间节奏、颜色和状态、组件、响应式以及需要的实际渲染证据。不是只套一个皮肤或只有 Token 表。

开发部分：代码遵循上述两种规格，能实际运行操作，说明哪些已经验证、哪些缺现实环境。达到目标后不重复追求主观零差异。

## 4. 源码与分发

- 8 个 Skills 的**唯一来源**都在 `skills/`。
- `plugins/product-ux` 和 `plugins/visual-system` 是插件打包源目录；运行 `python scripts/build-plugins.py` 产生两个可导入 ZIP。
- `personal-ui-delivery` 单独复制到相应 Agent 的 Skills 路径；安装 ChatGPT Plugin 不等于替所有本地 Agent 安装。
- 不需要上传旧聊天/截图到公开 GitHub。材料的作用是支持设计方法，具体项目另建自己的 canonical 文档。
