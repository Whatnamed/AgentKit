# ProxyLens UI 历史经验：第一轮方法候选

> 状态：研究草案（不是已审定 Skill，也不是最终跨项目规范）。整理来源为三个历史产品/UI 讨论窗口；原始档案和逐轮证据保留在本地私有资料中。尚未完成固定 Git 版本的源码复核及跨项目评估。

## 可复用候选

1. **先任务和事实，再页面和视觉**：对照真实能力、核心用户任务与数据语义，设计页面职责、信息层级和上下文转换，而非照功能清单堆页面。
2. **产品 / IA / 视觉 / 实现分层**：已确认事项需要独立权威来源。模板只能帮助表达，不能替新产品决定业务布局。
3. **比较方案不以数量取胜**：多页面、多控件或更多快捷操作不自动等于更成熟。逐项解释采纳、否决和保留理由。
4. **上下文状态需要设计**：筛选、时间窗、调查快照、页面返回、跨页下钻各自的继承和重置应有明确契约。
5. **状态真实性优先**：Loading、Error、Empty、Unknown、数据缺口和未来时间不应被随意合并或美化为“无数据”；具体状态取决于领域事实。
6. **参考图不是实现权威**：视觉探索用于选方向，再将有效原则沉淀为设计系统；不能从生成式页面照抄虚构数据、错误结构或品牌外观。
7. **设计系统深度匹配项目成熟度**：有理由的视觉原则、文字和组件角色、Token、交互状态、实现映射、QA 按需要逐步完善。
8. **视觉问题先查规范和真实实现**：分类“规范本身不适用、实现偏离、环境差异、规范缺项”；优先定位根因，再做最小纠正，避免同时任意调整字体、字重、行高和间距。
9. **实际字体与渲染优先于 CSS 声明**：核实字体打包、fallback、字符覆盖、真实字重、许可，以及叙述性文字与技术证据的字体角色；跨语言验证布局稳定和视觉对齐。
10. **视觉状态独立验收**：Light/Dark、hover/selected/focus、标签、图例、弹层、表面分层、低对比场景，需要真实渲染下检验；不能仅看 token 或构建成功。
11. **探索工具与正式产品隔离**：调色和字体对比工具可以临时建立，定稿后移除入口，不让实验选项污染生产配置。
12. **审查有价值门槛和停点**：只把错误事实、误导状态、关键任务中断、可复现明显回归等作为当前阻塞；多轮修补后回看完整改动，避免无限局部优化。
13. **不同验收层级不能混说**：静态代码检查、单测、浏览器效果和真实完整运行是不同证据；缺乏必要数据时记录 Deferred，而非虚构最终 PASS。
14. **职责清楚的文档和 Prompt**：稳定指令与进度分离；重大任务有独立执行文档，短启动 Prompt 引用权威计划，不反复复制全部上下文。

## 组织方式：仍待确认

初步方向为 Product & UX（`product-discovery` / `product-ia-interaction` / `product-ux-review`）、Visual System（`visual-system-extract` / `visual-system-adopt` / `visual-qa`）和独立的 `personal-ui-delivery`。这是七个**候选**，不是七份已经授权开发的 Skill。

具体产品的页面数、字体名称、颜色数值、品牌参照与技术语义只适合作为**版本化案例**，不作为通用强制规则。
