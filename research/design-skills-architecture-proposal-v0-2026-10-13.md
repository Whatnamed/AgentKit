# AgentKit 设计 Skills：方法架构提案 v0

> 日期：2026-10-13 · **历史 v0 研究草案；正式成品与用法以仓库 README、skills/ 和 plugins/ 为准。本草案中的七候选与强制 Eval 前置已被后续版本调整。**  
> 目的：把三份设计经历、既有可复用 Skill 的研究和用户自己的实践，组织为一套**可独立触发、可追溯、可测试、不会机械输出文档**的能力体系。

## 1. 资料各自贡献什么

| 来源 | 作为参考的层级 | 不应该做什么 |
| --- | --- | --- |
| **Morpho / Claude Design 设计系统导出** | **方法与交付结构**：完整设计系统需包含哪些方面、如何分层 Tokens、组件源码、类型、逐组件 Prompt、Source Map 与导出约束；探索“怎样制作、维护、交接一套设计系统” | 不复制无限画布、悬浮 AI UI、具体字体/颜色到其他产品；不将 115 文件的仓库导出包误认成包含原设计项目全部规范卡片与 UI Kit |
| **ProxyLens（冻结版本 + 3 段讨论原文）** | **过程、决策与真实打磨**：用户任务→信息架构/状态语义→视觉方案→实现→真实 QA；重点看否定、修正、字体问题、密度/表面与合理停点 | 不把具体页面、网络审计概念、个别补丁和用户阶段性的审美偏好晋升为通用强制规则 |
| **AgentBench（IA v2 + UX v2 + 视觉继承文档）** | **迁移与反例**：产品职责未定就开始移植视觉会发生什么；同一视觉语言如何映射到不同 IA、状态和真实操作；目标标准与已验收实现不同 | 不宣称当前目标 UI 已验收；不把它当成熟完成品的视觉示范，也不把它当 ProxyLens 或 Morpho 的业务克隆 |

这不是一条必须沿用相同外观的视觉继承链。用户明确说明，Morpho 的 Claude Design 系统在 ProxyLens 时主要是**架构、内容完整度、方法和交付组织**参考；AgentBench 则另外有明确的 ProxyLens Frozen v1 视觉迁移合同。

## 2. 三层资源模型：不要把所有内容写进 SKILL.md

1. **Skills：可执行行为合同**。只描述触发条件、输入/权威、决策方法、何时读取资源、要交付什么、遇到缺口如何降级/停止；短而可组合。
2. **Templates：按需填充的产物骨架**。没有信息不得硬填；允许跳过不适用章节。禁止每次执行 Skill 自动输出所有模板。
3. **Reference packs / Case studies：版本化事实与示例**。每个 pack 需有来源项目、路径、commit 或文件指纹、创建/核验日期、有效范围、是否已真实运行验收、字体/许可证限制、已知差异与仅供参考的部分。使用时只加载任务相关章节，不把全部案例默认注入。

公开库只存经脱敏的案例摘要、原创模板、可合法分发的源代码或索引。**原始聊天、截图及私有台账保留在 `private/`，不进入 public Git。**

## 3. 能力分组与触发边界

先保留 **7 个候选**，但并不强制生产七个；在小规模 Eval 后可合并或拆分。

| 归属 | 候选 Skill | 典型触发 | 最小价值输出 | 不该执行 |
| --- | --- | --- | --- | --- |
| Product & UX | `product-discovery` | 新产品目标模糊、用户任务和范围缺失 | 用户任务/对象/边界/关键假设与优先补缺项 | 未确认就画固定页面或选主题 |
| Product & UX | `product-ia-interaction` | 已有范围，需设计或改进 IA/流程 | 页面职责、核心路径、状态/恢复/异常合同、开放决策 | 把别的产品导航直接照搬 |
| Product & UX | `product-ux-review` | 审查已有方案、选择方案或判断是否可交付 | 关键缺口按影响排序、采纳/拒绝/待核验、停止点 | 为增加“完整感”堆页面和低价值功能 |
| Visual System | `visual-system-extract` | 从源代码/设计系统形成可复用参考包 | 版本索引、视觉角色/Token、组件状态、资产与差异说明 | 声称没有渲染证据的稿件已验收 |
| Visual System | `visual-system-adopt` | 新产品已有 IA，想采用指定视觉系统 | 角色映射、原样继承/适配/不继承清单、目标实现边界 | 继承源项目的业务 IA |
| Visual System | `visual-qa` | 已实现 UI，需要真实对照或视觉审查 | 不一致项及证据、复现条件、风险排序、pass/exception/deferred | 仅凭 CSS、构建成功宣称用户体验通过 |
| Standalone | `personal-ui-delivery` | Coding Agent 按已审定产品/设计规格交付 | 本轮执行前置、变动范围、必要测试、真实证据和收口条件 | 让执行 Agent 自行决定未确定的产品/架构方案 |

**路由**：一个入口问题选最小匹配能力；只有确实依赖上一阶段产物时再调用下一项。已有 IA 的任务不重跑 discovery；只做视觉 QA 的任务也不重新选风格。领域资料不完整时先标出缺口并做可安全进行的部分，不能伪造结论。

## 4. 先准备五种轻量模板

- `product-framing.md`：目标、用户任务、核心对象、当前事实、已决定/待决定、非目标。**不是所有新产品必须输出长 PRD**。
- `ia-and-interaction-contract.md`：页面职责、用户操作、跨页上下文、异常与恢复、状态真实性、最小验收。
- `design-system-pack-index.md`：设计意图、Tokens/文字/控件/组件、Light/Dark、源码与已验收状态、许可证、缺口。参考 Morpho 的资料体系，但不照搬其应用业务结构。
- `visual-adoption-map.md`：源版本、目标 IA、复用的视觉角色、需要改造的组件、禁止迁移的源业务布局、理由与例外。
- `visual-qa-evidence.md`：运行环境、窗口/语言/主题/状态、证据、问题严重度、延期前置条件与收口判断。

每个模板都应支持“本任务不适用/尚无可靠信息”，不强迫填满或机械输出。文字细节与反模式可放在各 Skill 的按需 references 中。

## 5. 高价值规范怎样下沉

把历史经验分成四种类型，避免大量“绝对化设计戒律”：

- **方法**：如先检查 IA 与状态语义、来源权威；可写进 Skill 的操作流程。
- **条件性验收标准**：如字体是否真的加载、DPI/Light/Dark/长文本状态；有适用条件的检查项。
- **个人偏好**：如信息密度、克制的辅助文案、偏好的协作流程；应允许项目显式覆写，不能把个人风格强加给其他人或项目。
- **案例与反例**：如 ProxyLens 具体字体、Inspector 色彩、AgentBench 题库/测试的不同布局、Morpho 画布组件；留在版本化 reference，不作为通用规则。

提炼材料已有 **30 条私有轮次定位候选**与**14 条公开初稿**；后续优先把“用户明确纠正”与“已核实源码事实”晋升为试行方法，对助手建议或单轮试验保留 `candidate` 状态。

## 6. 最小 Eval：用失败案例检验切分是否有价值

| 场景 | 期望行为 | 需要抓到的失败 |
| --- | --- | --- |
| A. 零散产品想法 | 补关键任务/对象/状态，不立即给漂亮 UI | 凭空设计页面、超长填表 |
| B. IA 未完而要求移植视觉 | 识别前置缺口，完成能做的部分 | 把视觉当产品方案替代品 |
| C. 从 Morpho 类设计系统提取 | 完整覆盖文件结构、组件 API、Source Map、资产限制与版本 | 只摘颜色和圆角，忽视交付内容 |
| D. ProxyLens → 陌生业务视觉迁移 | 复用字体、空间/表面和控件规则，保留目标业务 IA | 把源项目 Inspector/导航直接搬过去 |
| E. 视觉审查与停止 | 区分真实重问题、主观偏好、未验收和 deferred | 无尽 polish 或无证据判 PASS |

每个测试同时记录无 Skill 的基线和加载候选 Skill 的结果，关注**新增真实价值、错误继承、过度文档、遗漏、停止能力**，而不仅是行数/完成率。先用少量人工检查，不急着开发复杂 Eval 平台。

## 7. 分发与仓库：统一源码，按目标环境打包

- `skills/<skill-name>/SKILL.md` 为唯一可维护源文件；各自按需带 `references/` / `assets/`，不要把所有共享资料塞进一个巨大 `SKILL.md`。
- `templates/` 提供可选产物骨架；`references/case-studies/` 只放可公开的脱敏、定版示例。
- `plugins/` 只管理私人 Plugin 的组装入口和分发元数据；它们与 Codex/其他本地 Agent 的安装动作互相独立，不能把安装 ChatGPT Plugin 视为自动覆盖所有本地环境。
- 本仓库 `AGENTS.md` 只说明长期协作和隐私边界；当前工作进度不要写入其中。
- 暂不提交空 `skills/` 或过度构建脚本；真实需要时再创建。

## 8. 下一轮最小任务与明确停点

1. 把 Morpho 的 **设计系统交付结构**（不是颜色/画布 UI）做成一页带具体文件来源的样板索引；ProxyLens 的方法/视觉迭代和 AgentBench 的错配修正各保留一个去敏感案例。
2. 为第 3 节七个候选写**极简输入-行为-输出-停止**合同草案，找出重叠或缺口；只在有实际使用场景时调整数量。
3. 产出五份**短模板草案**，不填入项目无关内容，也不补虚构的完整业务需求。
4. 先用第 6 节场景做人工走查，决定首个值得正式制作的 Skill。**在本提案获审定前，不创建最终 `SKILL.md` / Plugin。**

停止条件：以上材料足以判断“遇到某类设计任务应该加载哪个 Skill、引用什么资料、交付什么、怎么验收”，则结束方案设计阶段；不因尚未研究所有第三方 Skills 就推迟试做。
