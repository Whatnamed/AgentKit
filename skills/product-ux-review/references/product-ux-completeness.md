# 产品/UX 复审：具体观察而非大而全 checklist

按本轮页面类型挑相关项，不要机械生成几十条意见。

## 从宏观到细节

- **产品与场景**：有没有遗漏用户的真实目的？功能是否能从头用到尾，不只是有个入口？模块归属合乎认知任务吗？
- **导航与上下文**：信息架构是否清晰？页面切换后数据、筛选和输入是保留、重置还是过期？返回时定位还在吗？
- **空间组织**：是否都是同级卡片，缺少真正的主次任务？Page/Section/Item/Metadata 的层级有没有靠实际内容形成？区域空白是否源自有意的密度选择，而非人为撑高；高密度是否牺牲辨认或操作？
- **页面小功能**：列表排序/筛选是否能清空？长名称能看全文吗？分组、选择、展开、导航的点击区域与语义是否混淆？是否可以继续上次未完成的工作？输入修改未保存怎么办？
- **动作/反馈**：提交时有没有 busy、成功/失败、部分成功和去重？危险动作是否告知范围；取消是否有效；没有权限或后端没实现时有没有假按钮？
- **信息文案**：是否每个标题都附同义解释句？真正重要的来源、原因和下一步有交代吗？没有数据、未知、估算、失败是否被错误合并？
- **完整状态**：首次使用、重复使用、空/很多数据、长内容、缩放、窄屏、键盘焦点、网络/权限错误、重启恢复。
- **决定和验收**：此项是确定的用户要求、方案建议还是运行证据？没有 runtime 就别说已验收。用户明确拒绝的建议不能下轮又出现。

## 借鉴但不照搬

ProxyLens 历史讨论中曾通过 A/B/C 比较发现“页面更多”不一定更好，字体/Inspector 的多轮修正说明需要先定位设计规范和代码偏差。AgentBench IA v2 区分“组内测试工作台”与“题库浏览目录”。这些案例提供问题识别方式，不能变成所有产品都采用相同导航或密度。
