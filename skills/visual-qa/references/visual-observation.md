# 视觉复审时应留意的常见根因

只选择和当前问题有关的项目；参考 ProxyLens 历史 UI 调整与 AgentBench 布局纠偏，不要原样继承两个产品的具体值。

| 症状 | 先判断 | 常见错误修法 |
| --- | --- | --- |
| 中文与英文字宽/高度明显不一致 | 字体资源是否成功加载、CJK fallback、face 权重映射、当前宿主 DPI | 按语言手工加 transform/padding |
| 标题/元信息/操作行显得松散或拥挤 | Page/Section/Group/Item 的真实层级与行高、内容分组 | 全局给所有元素加同一 gap |
| 侧栏与详情栏“黏成一片” | Surface 语义、分界、亮暗主题下的层次 | 只换单一背景色 |
| selected / hover / badge/semantic status 不可辨 | 行为状态和数据语义是否用了同一种强调色 | 给所有标签添加更多彩色 |
| 图标、点、竖线、文本底部不齐 | 字形 baseline、viewBox、真实几何中心和光学中心 | 只在单一字体/字号下写负 margin |
| 视觉继承看起来不像源系统 | 字阶、密度、文字节奏、控件几何、表面与弹层是否都继承 | 继续调品牌色，忽视页面层级 |
| 页面像 Demo/空盒子 | 产品布局和内容是否已决定、有无有效动作/真实数据 | 加填空副标题和虚假 KPI |
| 静态图不错，应用运行很糟 | 状态、响应式、字体、系统原生控件、滚动/焦点 | 把设计稿 PASS 视为完成 |

## 运行时判定

- 必须记录来源版本、当前 commit、目标宿主、窗口/缩放、主题、界面语言、状态/数据条件。
- 视觉对比支持观察法，也可辅助截图和计算样式；不要用未经许可的静态资源替代真实 UI。
- 缺少数据、运行时无法启动或只剩有限证据时，输出“尚未验证”并解释缺哪一环；这不是强迫用户重跑高成本测试的理由。
- 重要程度按实际用户影响评定：误导数据与不可操作界面优先，局部 1px 主观偏差视上下文处理。多轮修复后，进行一次整体回看并明确停止。
