# 页面与控件完整性参考（需要设计整页时阅读）

## 每个页面要回答什么

1. **身份与位置**：页面名称和职责、从哪里进入、当前项目/工作组/对象是谁、当前位置怎样显示、是否需要额外首页。
2. **视觉前的信息层级**：首屏先出现哪一个事实/任务、上下文和筛选放哪里、核心内容如何分块、元信息怎样退居其次；确定功能性的主区/辅区宽度优先关系、折叠与滚动区域，暂不赋予固定 CSS 像素。
3. **组件匹配认知任务**：浏览目录与正在执行工作的页面可以用不同结构；只有需要比较时才表格，只有需要筛选时才 Filter，不以流行“卡片+数字”取代任务组织。明确什么是可见内容、什么是按需 Inspector、Tooltip 或展开阅读。
4. **操作归属**：全局动作、对象动作、行内动作、危险动作、批量动作分别在哪里；主按钮是否真的能用；长标题、路径、错误文本是否会挤掉操作。
5. **提示文案纪律**：说明应表达用户不知道的重要事实、限制或下一步；不要默认每级标题后面都补同义副标题。没有数据的区域不靠空卡片占位。
6. **可变条件**：空/多项/长项、过滤无结果、分组切换、窗口变窄、侧栏收起、加载迟滞、保存失败、权限/数据不可用；条件变化后内容是否仍然可找。
7. **动作粒度**：行主体点击、Chevron 展开、更多菜单、复选框和内联操作互不错误触发；hover 和选中要符合真实行为，键盘和可访问名称清楚。
8. **流程结束**：完成后用户看到何种结果、下一步做什么、如何返回或继续，错误后什么必须保留。

## 需要落盘的“布局”并非视觉皮肤

即便还没有 Typography/颜色，也应决定“页面主要区块占据什么位置和信息优先级”“哪个模块与哪个模块为一组”“主任务和上下文的邻接关系”“列表与详情的交互空间”“什么内容应该隐藏以减少噪声”。这属于产品布局，不能把所有布局问题都推到视觉 Skill。

视觉 Skill 后续可调整内边距、间距量级、字阶、对齐与表面表达，但不得默默移除必要模块，或把一个复杂工作台改成只具备演示效果的卡片图。

## 逐页走查表

| 面向 | 设计问题 | 证据/决定 |
| --- | --- | --- |
| 页面职责 | 用户为什么来到这里，不来这里是否也能做任务？ | |
| 信息区域 | Page/Section/Group/Item 顺序、空间与优先级？ | |
| 对象操作 | 新建/修改/删除/归档/查看/继续各归属何处？ | |
| 微交互 | 筛选、排序、展开、选择、切换、输入、保存后如何反馈？ | |
| 状态与恢复 | 正常/空/未知/错误/重启/返回/长内容？ | |
| 可访问 | 键盘焦点、主次动作区别、文本溢出、缩放？ | |
| 不做的事 | 为什么不加这个页面/文案/控件？ | |

只检查当前任务涉及的行，不要求每次输出这一整张表。
