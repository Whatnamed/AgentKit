# 跨产品类型的 IA / 交互覆盖参考

当用户准备做**完整新产品、陌生领域或复杂改版**时才读取。这里提供“可能需要考虑的角度”，**不是通用功能清单**。根据真实用户任务、平台、内容、风险和已有决定，选相关项深入到页面/控件；不适用的项直接跳过。未知事实写候选，不伪造功能需求。

## 基础横向能力（按使用情境）

| 用户任务/对象特征 | 值得主动核对的产品问题 |
| --- | --- |
| 用户第一次接触 | 是否要创建项目/账户、导入数据、选择模板、权限授权、空状态与示例？可以跳过吗？无这些需求则无需强加引导 |
| 搜索与浏览 | 信息分类、标签、筛选/组合/清空、排序与结果数、无结果、跨页/历史位置、键盘查找 |
| 编辑与输入 | 输入验证、草稿与自动保存、未保存退出、撤销/重做、批量操作、保存冲突、历史版本、取消 |
| 反馈与风险 | 成功/失败/部分完成、任务进度来源、重试与幂等、不可逆行为确认、失败后保留用户成果 |
| 数据表现 | 数值来源、时效/分母、零与未知、估算与精确、比较口径、表格/图表选择、导出和可解释性 |
| 身份与权限 | 谁可查看/创建/修改/批准、访问受限的 UI、切身份/工作区后的状态、审计追溯 |
| 多端或多语言 | 窄屏/窗口缩放、输入方式、系统平台、不同文字长度、时区与本地化格式、离线能力 |
| 内容与文案 | 命名与概念词汇、说明的实际信息价值、列表截断/阅读全文、警告/空状态/错误的下一步、用词一致性 |
| 发现与复用 | 最近使用/固定/收藏/历史/复制等是否真正帮助目标任务，是否反而造成噪声 |
| 数据与环境丢失 | 刷新、断网、系统重启、外部应用失败、权限撤销、恢复/备份/删除边界 |

## 领域型模式：仅选有关的深入

| 产品类别/交互模型 | 除通用项目管理 UI 外容易漏掉的设计点 |
| --- | --- |
| **复杂桌面工作台/IDE/专业工具** | 密集信息区、Inspector/工作区焦点、键盘快捷键、命令入口、可拆面板与布局记忆、长任务恢复、路径与外部进程状态 |
| **内容/文档/知识库** | 树状目录与搜索、内容创建/版本、引用/关系、标签分类、草稿/阅读/编辑/分享、可用性与权限 |
| **协作/B2B/管理后台** | 工作空间与角色切换、审批与分派、批量动作、权限差异、数据可见范围、审计历史、多人变更冲突 |
| **电商/交易/预约** | 商品/服务选择、价格与库存/可预约性来源、购物车或多步提交、可取消/退款/失败恢复、准确状态及确认页 |
| **分析/财务/实验与观测** | 时间/人群/来源范围、过滤和钻取、精确性、缺失数据、不可比数据、刷新时效、长表格/导出 |
| **创作/图形/媒体/画布** | 工具模式与选择模型、缩放/平移、图层或对象关系、操作级 Undo、保存/版本、异步媒体导入和可视反馈 |
| **AI Agent/生成式产品** | 建议/草案/正式应用的界线、用户可控性、生成过程状态、引用和不确定性、成本与重试、记忆和上下文延续 |
| **移动、触控或设备交互** | 手势发现、可触目标、系统返回、安全区域、离线/弱网、传感器/设备权限与断连恢复 |
| **公共服务/强监管场景** | 身份、辅助技术、错误纠正、流程中断恢复、个人数据保护、可核实的专业/法律约束 |

这些类别不是互斥分类。新型产品可用其自己的任务特征组合，而不是塞进最相近的模板。

## 什么时候算真正“详细”

不是只有 sitemap 和“页面拥有搜索功能”。完整范围至少能回答：

1. 进入哪个页面、为什么是这个页面；主内容/辅内容怎样按**目标用户任务**组织；
2. 每个模块用真实什么数据，显示/隐藏条件、列表/详情/表格如何选择，最重要操作放哪里；
3. 用户具体点哪个控件，输入什么，反馈什么，成功/失败/取消后停留何处；
4. 数据初始、空白、未知、等待、错误、部分成功、权限/离线等**适用状态**的内容和可行动作；
5. 重要跨页状态、导航返回、筛选/选择/展开/草稿与外部工作是否保留和恢复；
6. 长内容、不同数据量、窄窗口/平台输入方式、键盘和可访问语义的边界；
7. 当前后端/数据能力是否真的存在，不能存在时 UI 怎样真实解释，而不是画一个假按钮。

如需要清楚说明布局，可用线框/区域草图/任务流程表辅助文本，但不要求每页都生成高保真原型。组件交互可查 [W3C ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/)；它给通用组件的键盘与语义模式，不代替产品 IA。

## 公开方法参考

- [GOV.UK Design System — Patterns](https://design-system.service.gov.uk/patterns/)：按用户任务和页面类别归纳设计模式，说明何时及如何应用，不只是组件列表。
- [Microsoft 365 Agents Toolkit — PRD + Scenario Design](https://github.com/OfficeDev/microsoft-365-agents-toolkit/blob/dev/.github/skills/prd-ux-design/SKILL.md)：PRD 负责意图与范围，独立的情境规范描述具体步骤、状态、边界与界面；不要照搬其复杂企业文件结构。
- [gstack — Plan Design Review](https://github.com/garrytan/gstack/blob/main/plan-design-review/SKILL.md)：在开发前找出 IA、状态、Journey、设计系统及响应式上的真实缺口。分数和强制逐题确认不适合本个人工作流。
- [W3C WAI — ARIA APG](https://www.w3.org/WAI/ARIA/apg/)：控件语义、键盘焦点与交互范式参考。
