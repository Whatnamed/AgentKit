# 产品前端：从 IA 到逐页完整交互

## 目标与边界

将产品功能与真实任务转换为**可直接指导前端实施的产品结构和页面/交互规格**。不是只输出站点地图、几张线框草图或 Demo；用户要求完整设计时，必须走到每个关键页面的区域划分、内容及优先级、组件职责、操作路径、状态差异、细节与边界。**产品结构和视觉表达分开**：本技能负责信息先后、区域关系、展开/折叠、主/次动作、栅格与密度的功能需求；不提前锁定字体、颜色、阴影和视觉 Token。

不必按固定步骤重新开始。已有完整产品规格时直接设计页面；已有页面框架时从详细布局和交互缺口继续；局部问题只做局部。

## 操作顺序（完整产品任务按深度推进）

1. **事实与权威**。阅读当前已确认的产品目标、功能、领域对象、可用数据与原有 UX 约束。分别标注目标规格、当前运行事实、历史方案、尚未决定事项；不让旧 UI、组件复用或设计系统代替产品判断。多源矛盾时可读 [证据分级参考](references/evidence-and-state.md)。缺少关键输入时用最少问题澄清，能提出合理候选的先推进。
2. **任务模型与对象模型**。明确用户为何进入、主要行动是什么、怎样确认成功，以及对象之间的关系、身份和生命周期。按真实使用频率与风险区分主任务、次任务、例外任务；补齐必要的查找、筛选、创建、编辑、撤销、保存、清理、返回等动作（仅在适用时）。新产品或陌生领域按需读取 [跨产品类型与任务模式参考](references/adaptive-product-patterns.md)，根据其实际类型选择检查角度，而不是以 ProxyLens/AgentBench 的工作台模型替代所有产品。
3. **整体 IA 与导航**。决定一级/二级页面、页面职责、共享 shell、详情/侧栏/弹层的职责、跨页跳转及回退。避免为功能列表一项建一页，也避免因为容易复用代码而让不同认知任务使用相同布局。
4. **逐页空间蓝图**。这是重要的独立步骤：对每个关键页面明确 Page/Section/Group/Item/Metadata 的层级、从上到下或从左到右的区域顺序、每个模块展示的真实数据、信息密度、占用空间原则、页面宽窄状态、列表/卡片/表格/Inspector 的使用理由、空白和滚动位置、主操作的邻近关系。可以用文字方框、区域表或低保真线框；不要只给大概一句“左栏+内容区”。详见 [页面细节规范](references/page-and-control-detail.md)。
5. **逐控件与交互合同**。对关键按钮、行项目、筛选、搜索、排序、表单、Tab、弹层、切换、可展开区域、状态提示逐一明确可见标签、触发动作、反馈、禁用/等待、键盘/触屏、取消和撤销、焦点及危险操作边界。区分 selection / expansion / navigation 等不同状态，不能“一点全触发”。详见 [状态与上下文参考](references/interaction-and-state.md)。
6. **走真实任务与全状态矩阵**。覆盖首次使用、正常完成、多数据与长文本、无数据、Loading、未知、错误、部分成功、权限/网络/依赖不可用、恢复与重启（依产品而定）。写明跨页上下文如何继承/重置、回到哪里、操作失败后保留什么、数据来源与真实程度；不能凭页面设计伪造后端能力。
7. **补漏与收敛**。检查是否只有主干没有细节：辅助操作入口是否合理、内容截断能否获取全文、操作是否有状态反馈、弹层关闭能否回到原焦点、刷新/切组是否损失工作、数值与文案是否误导、哪些信息只在真正有价值时显示。高影响缺口应解决，低价值装饰可舍弃。明确已决定、候选与 deferred。

## 交付深度按任务而定

- **完整新产品**：先提供 IA/导航与关键用户流程，可用 [整体 IA 合同骨架](assets/ia-contract.md) 整理；随后逐页输出细节规格（不是仅“将来需要考虑”），直到核心页面、关键操作、状态、异常和小功能足以交付开发。可分会话分阶段推进，但最终要形成可追踪、无关键空洞的一组 canonical 产品/UX 文档。
- **逐页规格最低包含**：页面目标和入口、空间区域与层级、每个模块的内容/操作/顺序/显隐规则、列表或图表选择理由、关键组件与交互、跨页/状态/异常/窄屏、验收路径、开放决策。可用 [详细页面合同模板](assets/page-spec.md)，不要机械填无关栏目。
- **局部讨论**：直接回答当前控件/行为的方案及理由，不自动生成整套文档。
- 最重要决策尚未定时给出 1—3 个清晰方案、用户影响和推荐，不转交 coding agent 自行定义。用户确认后记入相应权威文档；下一轮不重开已确认问题。

## 与其他技能交接

- 功能与任务不清：先用 `product-discovery` 补关键需求。
- 页面体验较完整：可用 `product-ux-review` 查遗漏；这是可选审查，不是无限循环。
- 视觉系统：交给 `visual-system-create` 或 `visual-system-adopt`，仅在产品结构充分明确后处理视觉角色。视觉阶段可以对微观排列提出改进，但要显式记录对已确认产品结构的影响。
- 前端实现：交给 `personal-ui-delivery`，以已确认规格为依据。

**完成条件**：目标范围内每个重要用户任务都有入口→操作→状态反馈→完成/失败→返回/恢复；每个关键页面有可开发的区域与控件细节，且未决点不影响下一阶段。不要将“只有大框架”标成产品前端设计完成。
