# 视觉设计系统提取

## 适用与输入

针对**指定来源**整理可复用、可检索、可交付的设计系统，不必从零重设计产品。来源可以是 Git commit、已验收组件库、真实应用、文档或图片；来源不同，能作出的真实性声明也不同。

若用户只要某个颜色、组件或局部风格，回答该问题即可，不强行产出完整设计系统。如果来源不完整，先提取能验证的部分，标明缺失，不凭主观推测补齐。

## 执行

1. **冻结来源范围**：记录仓库/版本/commit/文件与采样时间、目标技术栈、是否有实际运行。区分“官方设计规范写了什么”“源码目前实现什么”“运行时真正显示什么”。禁止把最新 main 默认为历史视觉基线。
2. **识别设计意图与适用条件**：提炼产品的视觉角色、信息密度、层次与交互调性；分离可跨项目重用的表达方法和当前业务专有对象、导航及数据概念。
3. **分层提取**：检查主题与语义 Token、字体与文字角色、字重/中英文 fallback/行高、间距与几何、表面/阴影/边框、图标、动效与无障碍；不要只摘几个 Hex 值。按需要加载 [提取覆盖与证据分级](references/coverage-and-evidence.md)。
4. **按组件形成使用合同**：列组件职责、Props/API、Variants、状态、内容与尺寸极端情况、交互和组合规则。对源码、图片和纯文字设计的覆盖差异显式标明。
5. **建立映射与打包边界**：Token/组件/样式分别定位至仓库文件与版本，说明依赖、资产和字体许可证、导出方式、运行平台以及尚未建模的部分；对不可再分发素材只给源索引，不打包字体或私有截图。
6. **验证与纠偏**：区分设计说明、源码检查、浏览器运行、真实宿主环境和独立人工验收；关键视觉主张无对应证据则 `unverified`。运行环境允许时优先抽查典型页面、Light/Dark、hover/selected/focus、空白与异常、长中英混排和缩放。
7. **完成并定位后继任务**：只输出来源所支持的视觉系统快照、可移植视觉角色、业务专有边界、遗漏/冲突、验收等级。用户后续若要移植到新产品，必须以**新产品既定 IA** 为前提另做角色映射，而不是复制源产品页面。

## 交付尺度

- 局部提取：紧凑回答对应 Token/组件及出处。
- 整套设计系统：使用 [Design System Pack 索引模板](assets/design-system-pack-index.md) 的相关章节，列来源、设计语言、Tokens、Typography、组件与状态、源文件路径、异常与未覆盖部分。
- 输出不必复刻原项目的全部代码；完整实现资源应通过明确许可证及需求后再打包。
- 所有版本声明必须有证据；缺少实际截图/宿主/字体加载验证时不得写“已完成视觉验收”。

## 停点

来源追踪可复现，涵盖本任务需要的视觉层次及组件状态，业务专属内容和不能证实的地方明确分离，并能指引后续移植或 QA，即可交付。不因追求“最完整”而继续无目标采集。
