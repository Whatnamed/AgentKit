# 从零创建视觉体系：细节与迭代参考

## 每一层选择都需要原因

- **风格身份**：安静分析工作台、创作空间、消费应用等需要不同的密度、色彩策略与表面；不能默认所有项目都套同一品牌或某个流行模板。
- **调色**：不是选 5 个好看的 Hex。至少明确 canvas / navigation / workspace / surface / raised / inset / hover / selection / focus / border / text levels / semantic states，各自对比度和 Light/Dark 关系。限制装饰色，不与业务状态冲突。
- **Typography**：Narrative（标题、正文、辅助文案）、UI Control、Monospace/data 字体的角色；中文/英文/混排的 fallback、真实文件/许可、字重映射、字形宽度、数字对齐与光学居中。明确字号、字重、行高、字距；改变字体后重新看各级排版和组件高度。
- **Spacing rhythm**：区分 Page 边距、Section 间隔、Group/Control 间隔、Item 内部间距、标题与辅助信息、表格行高；不能仅因“留白高级”就把每层 padding 加大，也不能一味紧凑导致无法扫描。让密度从真实信息结构出发。
- **形状与表面**：分层通过对齐、背景变化、线条与阴影协同，避免满页都是相同轮廓的卡片；选中、hover、focus 和语义状态既要区分又要相容。Modal/Popover/Tooltips 和普通常驻栏位不混淆。
- **图标与动效**：图标大小、stroke、对齐、点击目标；动效只解释状态或空间变化，提供 reduced motion。
- **组件全面性**：输入/选择/日期、按钮、多状态标签、工具条、列表与行项、导航、侧栏、弹层、表格、空/错误/加载、危险操作以及需求中出现的领域组件。按真实需求覆盖，不机械创建大 UI 库。
- **适配**：不同窗口/缩放/长名称/中英混排/状态拥挤时，允许局部例外但仍保留同一设计语言。

## 持续迭代的方法

1. 明确用户指出的是“视觉不喜欢/难以辨认/与规范不一致/实际字体替代/产品布局不合理”哪一种。
2. 选代表页面的有效状态，先把实际渲染与预期并排。
3. 找可能的局部根因，例如容器 padding vs line-height vs font fallback vs SVG viewBox；优先改少量有因果关联的参数。
4. 显示前后差异，记录是否采用。若是方向探索，可保存 2—3 套临时候选；定稿后不要把实验控制永久加进生产 UI。
5. 被采用的规则同步到 Token/组件/范例；如果该调整是页面业务例外，不改全局 Token。
6. 只有真实运行与关键场景检查后才能说实现验收，静态稿结束只说“方向确定”。

## 与产品布局的关系

已定的一级导航、区块职责、动作入口和状态不能随视觉重做。视觉可以提出更好的微观组织（局部对齐、分组方式、对比层次、紧凑密度）；若因此影响业务流程，先显式交回产品 IA 决策。
